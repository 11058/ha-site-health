# Site Health — здоровье сети MikroTik в Home Assistant

[![HACS Custom](https://img.shields.io/badge/HACS-Custom-41BDF5.svg)](https://hacs.xyz/)
[![Validate](https://github.com/11058/ha-site-health/actions/workflows/validate.yml/badge.svg)](https://github.com/11058/ha-site-health/actions/workflows/validate.yml)

Одна страница в сайдбаре HA — «Здоровье сети» — для объекта, где вся сеть
построена на MikroTik (RouterOS 7):

- **Каналы связи** — WAN-порты (DHCP-клиенты), скорость приёма/передачи,
  проверки netwatch (пинг, потери), туннели WireGuard (давность handshake).
- **Устройства** — главный роутер и остальные MikroTik (радиобаза, мосты, точки):
  на связи, CPU, температура, аптайм, версия.
- **Радиомосты** — уровень сигнала и скорости по каждому линку.
- **Клиенты по сегментам** — Семья / Гости / Умный дом / Видео / Админ / …
  (по VLAN), кто в сети, через какой Wi-Fi, с каким сигналом.
- **Домашние и админы** — у Wi-Fi-клиентов в гостевой сети кнопки «В домашние» /
  «В админы»: мастер по шагам (с картинками для iPhone, Android, Mac, Windows)
  проводит через отключение «частного адреса Wi-Fi», сам находит устройство после
  переподключения (новый MAC, время подключения, имя) и добавляет его MAC в
  `/interface wifi access-list` главного роутера с VLAN домашних (30) или админа (99).
  Обратно — «Убрать из домашних / админов». Устройства умного дома, камеры и пр.
  попадают в свои сети по SSID или порту коммутатора — их панель не трогает.
- **4G-роутер Тандем-4GT** (Микродрайв, NetOS/OpenWrt) — оператор, активная SIM
  из двух, регистрация, LTE-диапазон, RSRP/RSRQ/SINR/RSSI, температура, время на
  связи; переключение SIM, «Переподключить сотовую связь» (новая сессия, 10–30 с)
  и «Перезагрузить роутер» (1–2 мин) — в панели с подтверждением и кнопками в HA
  для автоматизаций. Данные — через его же веб-интерфейс (LuCI), на модеме
  ничего не настраивается. USSD на этой прошивке не работает, поэтому баланса нет.
- **Коммутаторы PS308GV3 / PS208GV3** (web-smart PoE) — порты с линком и скоростью,
  VLAN каждого порта, PoE по портам и суммарно, температура; кто подключён к какому
  порту (по таблице MAC — с именами клиентов). Управление: VLAN порта (access или
  транк; аплинк к роутеру защищён), перезапуск порта — передёрнуть питание камеры,
  PoE вкл/выкл. HA входит в коммутатор лишь на мгновение при опросе: прошивка держит
  одну веб-сессию, и её веб-интерфейс остаётся доступен.
- **Каналы связи любого типа** — PPPoE, DHCP (в т.ч. за 4G-роутером), LTE-модем в USB (сигнал
  RSRP/SINR, оператор), статический WAN-порт (например, к отдельной LTE-коробке MikroTik — её сигнал тоже
  показывается). Для каждого канала — маршруты по умолчанию по таблицам (с рекурсивными шлюзами), роль
  «активный / резерв / только по правилам», правила распределения трафика (mangle mark-routing) с пометкой
  выключенных, служебные маршруты (DPI-контейнеры, туннели) отдельно, проверки netwatch со скриптами.
- **Wi-Fi любого типа** — wifiwave2 (в т.ч. CAPsMAN: клиенты по точкам доступа) и старый `wireless`
  (RB951 и т.п.): «В домашние / В админы» пишут в нужный access-list.
- **Админский VPN (WireGuard)** — кнопка «Создать»: HA в этот момент делает пару ключей, добавляет пир
  с публичным ключом на админский WireGuard-интерфейс роутера (свободный адрес в админской сети, маршрут /32)
  и один раз показывает конфиг — QR для телефона и файл `.conf` для скачивания. Приватный ключ нигде не
  хранится. Внешний адрес подставляется из MikroTik Cloud или публичного IP канала; если объект за NAT —
  панель предупредит. Созданные так подключения можно удалить из той же панели.
  **Выбор шлюза:** «напрямую» (сам роутер объекта, если у него белый адрес) или через **VPN-шлюз** провайдера —
  хаб с белым адресом, чей туннель доходит до объекта. HA не получает на хабе никаких прав: скрипт на хабе раз
  в минуту забирает у HA публичные ключи этого объекта и сам добавляет/удаляет пиры — только в сети клиентов
  этого объекта (по /24 на объект), а его firewall пускает эту сеть только в подсети объекта. Скрипт для хаба
  выдаёт мастер «Добавить VPN-шлюз».

Плюс обычные сущности HA для истории и автоматизаций и сервисы
`site_health.set_device_segment`, `modem_select_sim`, `refresh`.

## Как это работает

Интеграция опрашивает RouterOS по **REST API** (HTTPS, `www-ssl`). Скриптов на
роутерах не нужно.

**Что делаете вы — один раз на каждое устройство:** вставляете в терминал
MikroTik блок команд, который **сгенерирует сама интеграция** при добавлении
(адрес HA и случайный пароль уже подставлены). Блок:

- создаёт самоподписанный сертификат и включает `www-ssl` **только для адреса HA**
  (если www-ssl уже был включён — лишь добавляет HA к разрешённым адресам);
- создаёт группу и пользователя `ha-infra`: на главном роутере — чтение и запись
  (запись нужна для списка домашних), на остальных — только чтение; без ssh,
  winbox, policy, sensitive (пароли и ключи не видны);
- на главном роутере — правило firewall `input`, пускающее HA к REST.

Повторная вставка ничего не дублирует.

**Что интеграция делает сама** (на главном роутере, через REST, можно отключить в настройках):

- находит остальные MikroTik через таблицу соседей роутера и предлагает их добавить;
- добавляет правило `forward`, чтобы HA доставал до REST радиомостов в их подсети
  (перед первым запрещающим правилом forward);
- добавляет пробы `netwatch` до 8.8.8.8 и 1.1.1.1, если их ещё нет;
- обо всём, что поменяла, пишет уведомлением в HA. Все её правила помечены
  комментарием `site-health: …`.

Если логин уже есть — выберите «У меня уже есть логин» и введите его.
Готовые скрипты для ручной настройки лежат в `mikrotik/`.

## Установка

1. HACS → Integrations → ⋮ → Custom repositories → `https://github.com/11058/ha-site-health`, тип *Integration*.
2. Установить **Site Health**, перезапустить HA.
3. Настройки → Устройства и службы → Добавить → *Site Health*: название объекта,
   адрес главного роутера в сегменте HA (подставляется шлюз HA, например 10.5.20.1), «Сгенерировать скрипт» → вставить блок в терминал
   роутера → «Отправить».
4. В карточке интеграции — **Добавить устройство** → выбрать найденный MikroTik →
   вставить его блок в терминал этого устройства → «Отправить».
5. 4G-роутер: в карточке интеграции — **Добавить 4G-роутер**, адрес подставится
   (шлюз WAN), логин его веб-интерфейса.
6. Коммутаторы: **Добавить коммутатор** — адреса предложит роутер (из своих проверок
   netwatch), нужен только пароль веб-интерфейса.
7. В сайдбаре появится **Здоровье сети**.

## Разработка

```bash
uv venv -p 3.13 && uv pip install homeassistant pytest ruff
pytest tests -q && ruff check . && ruff format --check .
```

Тесты не требуют HA и роутера: парсеры проверяются на фикстурах в формате REST
RouterOS 7 (`tests/fixtures/`).
