# Site Health — здоровье сети MikroTik в Home Assistant

[![HACS Custom](https://img.shields.io/badge/HACS-Custom-41BDF5.svg)](https://hacs.xyz/)
[![Validate](https://github.com/11058/ha-site-health/actions/workflows/validate.yml/badge.svg)](https://github.com/11058/ha-site-health/actions/workflows/validate.yml)

Одна страница в сайдбаре HA — «Здоровье сети» — для объекта, где вся сеть
построена на MikroTik (RouterOS 7):

- **Каналы связи** — WAN-порты (DHCP-клиенты), скорость приёма/передачи,
  проверки netwatch (пинг, потери), туннели WireGuard (давность handshake).
- **Устройства** — главный роутер и остальные MikroTik (радиобаза, мосты, точки):
  на связи, CPU, температура, аптайм, версия.
- **Радиомосты** — уровень сигнала и скорости по каждому линку.
- **Клиенты по сегментам** — Семья / Гости / Умный дом / Видео / Админ / …
  (по VLAN), кто в сети, через какой Wi-Fi, с каким сигналом.
- **Список домашних** — кнопки «В домашние» / «В гости»: MAC добавляется в
  `/interface wifi access-list` главного роутера с `vlan-id` домашнего VLAN,
  клиент переподключается. Новые устройства по умолчанию остаются в гостевой сети.

Плюс обычные сущности HA (сенсоры, binary_sensor) для истории и автоматизаций,
и сервисы `site_health.add_family_device` / `remove_family_device` / `refresh`.

> В планах: 4G-роутер Тандем-4GT-OEM (две SIM: активная, состояние, сигнал).

## Как это работает

Интеграция опрашивает RouterOS по **REST API** (HTTPS, `www-ssl`). Скриптов на
роутерах не нужно.

**Что делаете вы — один раз на каждое устройство:** вставляете в терминал
MikroTik блок команд, который **сгенерирует сама интеграция** при добавлении
(адрес HA и случайный пароль уже подставлены). Блок:

- создаёт самоподписанный сертификат и включает `www-ssl` **только для адреса HA**
  (если www-ssl уже был включён — лишь добавляет HA к разрешённым адресам);
- создаёт группу и пользователя `ha-infra`: на главном роутере — чтение и запись
  (запись нужна для списка домашних), на остальных — только чтение; без ssh,
  winbox, policy, sensitive (пароли и ключи не видны);
- на главном роутере — правило firewall `input`, пускающее HA к REST.

Повторная вставка ничего не дублирует.

**Что интеграция делает сама** (на главном роутере, через REST, можно отключить в настройках):

- находит остальные MikroTik через таблицу соседей роутера и предлагает их добавить;
- добавляет правило `forward`, чтобы HA доставал до REST радиомостов в их подсети
  (перед первым запрещающим правилом forward);
- добавляет пробы `netwatch` до 8.8.8.8 и 1.1.1.1, если их ещё нет;
- обо всём, что поменяла, пишет уведомлением в HA. Все её правила помечены
  комментарием `site-health: …`.

Если логин уже есть — выберите «У меня уже есть логин» и введите его.
Готовые скрипты для ручной настройки лежат в `mikrotik/`.

## Установка

1. HACS → Integrations → ⋮ → Custom repositories → `https://github.com/11058/ha-site-health`, тип *Integration*.
2. Установить **Site Health**, перезапустить HA.
3. Настройки → Устройства и службы → Добавить → *Site Health*: название объекта,
   адрес главного роутера в сегменте HA (подставляется шлюз HA, например 10.5.20.1), «Сгенерировать скрипт» → вставить блок в терминал
   роутера → «Отправить».
4. В карточке интеграции — **Добавить устройство** → выбрать найденный MikroTik →
   вставить его блок в терминал этого устройства → «Отправить».
5. В сайдбаре появится **Здоровье сети**.

## Разработка

```bash
uv venv -p 3.13 && uv pip install homeassistant pytest ruff
pytest tests -q && ruff check . && ruff format --check .
```

Тесты не требуют HA и роутера: парсеры проверяются на фикстурах в формате REST
RouterOS 7 (`tests/fixtures/`).
